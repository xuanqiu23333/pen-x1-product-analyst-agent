# PEN-X1 Product Analyst Agent Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a stable local PEN-X1 product-analysis interview demo with a traceable ten-skill workflow, a React dashboard, evidence controls, a validated Markdown report, and an offline DEMO_MODE.

**Architecture:** FastAPI keeps an in-memory typed `AnalysisState` per run and invokes ten isolated deterministic-first skills in a sequential workflow. JSON/CSV fixture providers and a mock LLM make DEMO_MODE independent of credentials and the network; an optional DeepSeek provider is isolated behind the same interface. React polls one run and renders the pipeline, structured results, risk evidence, gates, decision, and report.

**Tech Stack:** Python 3.11, FastAPI, Pydantic v2, Pandas, pytest, React, TypeScript, Vite, Tailwind CSS, npm.

**Spec:** `docs/superpowers/specs/2026-09-07-pen-x1-demo-design.md`

## Global Constraints

- Work only inside `D:\Projects\pen-x1-product-analyst-agent`.
- Use Conda environment `pen-x1-agent` with Python 3.11; never create a venv.
- Do not use Docker, Redis, external databases, scraping, WebSockets, or system-level configuration.
- Never store or expose API keys; `.env` stays gitignored and the frontend never calls DeepSeek.
- `DEMO_MODE=true` must complete all ten skills without network access.
- Mark supplied facts as `FACT`, fixtures as `PUBLIC_FIXTURE`, reviews as `SAMPLE`, financial inputs as `SCENARIO`, and absent data as `UNKNOWN` or `NEED_VERIFY`.
- Python, not the model, performs review aggregation, risk scoring, and financial calculations.
